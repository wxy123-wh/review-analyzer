# 项目改进计划

## 1. 当前背景

本项目当前已从蓝牙耳机评论分析 MVP 升级为“通用电商商品评论 VOC 分析”的改造中间态。现有代码已经具备真实评论导入、前端商品采集配置、商品级 UX 标签绑定、后端分析、问题优先级计算、趋势查询、词云、竞品对比、动作登记、验证结果和前端展示等 MVP 能力；NLP 服务已改为 LLM 优先、本地规则兜底。后续仍需要继续完善采集自动导入、质量抽样评估、产品迭代优先级和报告导出。

为了提升项目完整度和答辩说服力，后续目标是将系统升级为：

> 基于 LLM 的电商产品评论 VOC 分析与产品改进决策系统。

系统不再只限定蓝牙耳机，而是支持不同电商商品品类。核心链路应从真实评论采集开始，经过数据清洗、LLM 语义分析、问题归因、优先级计算、正面卖点分析和产品迭代建议，最终在前端形成可视化决策看板。

本次合并改造的关键原则是：

- `aspect` 不再作为核心业务维度，只保留为旧接口和旧图表兼容字段。
- 核心维度改为 `uxPrimaryLabel + uxSecondaryLabel`，其中 UX 二级标签负责问题、趋势、词云、对比和卖点聚合。
- 每个商品绑定一套 UX 标签组合；新评论导入同一商品后，继续使用该商品绑定 taxonomy 重新分析。
- 前端提供“采集配置”入口，用户输入商品链接即可启动 crawler 服务任务，不需要每次重写爬虫脚本。

## 2. 参考项目与借鉴方向

### 2.1 Crawling-User-Reviews-from-JD.com

<https://github.com/Huangirl710/Crawling-User-Reviews-from-JD.com>

本项目可借鉴：

- 断点续传。
- 采集进度记录。
- 风控/验证码出现时停止并提示人工处理。

本项目不应直接照搬：

- 京东特定页面结构。
- 京东特定接口字段。
- 任何绕过验证码、绕过风控或破坏平台规则的逻辑。

本项目采集模块建议使用：

- Python。
- Playwright 或 DrissionPage。

- 合规 API、第三方数据接口或公开可访问页面数据。

## 3. 目标数据流

完整系统目标数据流如下：

```text
商品 ID / 商品链接
  -> 前端采集配置
  -> 商品绑定 UX 标签组合
  -> Python crawler 服务采集
  -> raw_reviews.jsonl
  -> 数据清洗
  -> cleaned_reviews.jsonl
  -> LLM 情感分析
  -> LLM UX 标签诊断
  -> LLM 正面卖点提炼
  -> structured_reviews.jsonl
  -> 后端导入数据库
  -> 问题优先级计算
  -> 趋势分析
  -> 竞品对比
  -> 正面卖点分析
  -> 产品迭代优先级
  -> 前端可视化看板
  -> 报告导出与答辩材料
```

当前系统实际数据流如下：

```text
商品链接 / 真实采集或人工整理的评论
  -> 前端绑定 UX 标签组合
  -> POST /api/v1/crawl/start 或 Python crawler CLI
  -> raw_reviews_{productCode}.jsonl
  -> POST /api/v1/reviews/import
  -> reviews_raw
  -> analysis/start
  -> nlp-service 按商品 taxonomy 做 LLM 结构化分析或本地规则降级
  -> review_aspects / issue_clusters / issue_scores
  -> issues / compare / trends / wordcloud / validation
  -> Vue 前端展示
```

需要继续增强的是采集完成后的自动导入：

```text
真实评论采集
  -> 数据清洗
  -> 自动导入同一 productCode
  -> 自动触发 analysis/start
```

以及后半段增强：

```text
负面强度质量评估
标准原因人工覆盖
Aha Moment
迭代优先级
质量评估
图表报告
```

## 4. 分阶段改进计划

### 阶段 0：保护现有主链路

目标：先保护当前已经能跑的真实导入和 UX 标签分析链路，避免重构时把已有功能弄坏。

任务：

- 保留 `POST /api/v1/reviews/import`。
- 保留 `POST /api/v1/analysis/start`，并允许传 `taxonomyId`。
- 保留 `issues`、`compare`、`trends`、`wordcloud`、`actions`、`validation` 接口。
- 保留前端现有模块。
- 保留 legacy `aspect` 字段作为兼容返回，但不要再把它作为新功能主维度。
- 补充或修复后端测试运行环境。

验收标准：

- 前端测试通过。
- NLP 测试通过。
- 后端测试能够通过 Maven 或 Docker 跑起来。
- 当前真实评论流程不因新增模块失效。

### 阶段 1：评论采集模块

目标：新增 Python 评论采集模块和前端商品链接入口，将外部评论保存为原始 JSONL。

建议目录：

```text
crawler/
  taobao_reviews.py
  jd_reviews.py
  common/
    writer.py
    dedupe.py
    progress.py
  output/
    raw_reviews.jsonl
    crawl_progress.json
```

建议技术：

- Python。
- Playwright 或 DrissionPage。
- `json` / `jsonlines`。
- `hashlib` 做去重 key。
- `time.sleep` 做限速。
- `tenacity` 做重试。

输出字段：

```json
{
  "source": "taobao",
  "sourceReviewId": "tb_10001",
  "productCode": "600530677643",
  "category": "bluetooth-earphone",
  "rating": 4,
  "content": "蓝牙偶尔断连，续航一般。",
  "reviewTime": "2026-06-01T10:20:00",
  "skuInfo": "黑色 标准版"
}
```

验收标准：

- 可以生成 `crawler/output/raw_reviews.jsonl`。
- 同一评论不会重复写入。
- 程序中断后可以继续。
- 出现验证码或风险提示时停止并提示人工处理，不实现绕过。

当前完成情况：

- 已下载参考仓库到 `.tmp/external/Crawling-User-Reviews-from-JD.com`。
- 已新增 `crawler/jd_reviews.py`，采用 DrissionPage 浏览器辅助采集、网络响应监听、JSONL 输出、去重和进度记录。
- 已新增 `crawler/service.py`，提供 `POST /crawl/start` 与 `GET /crawl/jobs/{id}`，后端可从前端商品链接转发启动。
- 已新增后端 `POST /api/v1/crawl/start` 与 `GET /api/v1/crawl/jobs/{id}`，在 `sync_jobs` 中记录 `browser-crawler` 状态。
- 已新增 `crawler/import_reviews.py`，可调用后端 `POST /api/v1/reviews/import`。
- 已新增后端导入接口，导入成功后返回 `READY_FOR_ANALYSIS`，下一步调用 `POST /api/v1/analysis/start`。
- 当前缺口：crawler 采集完成后还需要手动或脚本调用导入接口；后续可做成采集任务完成后自动导入。

### 阶段 2：数据清洗模块

目标：将原始评论清洗成可分析文本，并输出清洗统计。

建议目录：

```text
pipeline/
  clean_reviews.py
  output/
    cleaned_reviews.jsonl
    removed_reviews.jsonl
    cleaning_summary.json
```

清洗能力：

- 空文本过滤。
- 无效 JSON 过滤。
- HTML 标签和 HTML 实体清理。
- 零宽字符、异常换行和多余空白处理。
- 精确重复评论过滤。
- 保留默认好评、短评论、低信息评论、普通中性评论和所有有效差评。
- 输出被删除评论和清洗摘要，方便答辩解释数据质量。

本阶段采用保真清洗，不做：

- 默认好评过滤。
- 低信息量过滤。
- 情感倾向过滤。
- 按评分过滤。
- 文本相似度去重。

可借鉴：

- 参考项目中的 `clean_reviews.py`。

验收标准：

- 输出有效评论。
- 输出被删除评论。
- 输出清洗摘要，例如原始条数、有效条数、删除条数、删除原因分布。

当前完成情况：

- 已新增 `pipeline/clean_reviews.py`。
- 默认输入 `crawler/output/raw_reviews.jsonl`。
- 默认输出 `pipeline/output/cleaned_reviews.jsonl`、`removed_reviews.jsonl`、`cleaning_summary.json`。
- 已新增 Python 测试，验证 HTML 清理、空内容、无效 JSON、精确重复，以及默认好评和短评论保留。
- 后端 `POST /api/v1/reviews/import` 已支持可选 `cleaningSummary`，并写入 `data_quality_runs`。
- 已新增 `GET /api/v1/data-quality` 返回最近一次清洗统计。

### 阶段 3：LLM 情感分析与负面诊断

目标：用 LLM 和商品绑定 taxonomy 替代固定 aspect 规则，得到更完整的语义标签。

建议目录：

```text
pipeline/
  llm_sentiment.py
  llm_negative_diagnosis.py
  prompts/
    sentiment_prompt.md
    negative_diagnosis_prompt.md
```

建议环境变量：

```text
OPENAI_API_KEY
OPENAI_MODEL
OPENAI_BASE_URL
OPENAI_BATCH_SIZE
OPENAI_SLEEP_SECONDS
OPENAI_MAX_RETRIES
OPENAI_TIMEOUT_SECONDS
```

LLM 情感输出：

```json
{
  "sentiment": "NEGATIVE",
  "dimension": "产品体验",
  "reason": "蓝牙断连影响使用",
  "confidence": 0.91
}
```

负面诊断输出：

```json
{
  "negativeIntensityScore": 3,
  "negativeIntensityLevel": "核心痛点",
  "uxPrimaryLabel": "产品硬件",
  "uxSecondaryLabel": "连接与稳定性",
  "standardizedReason": "蓝牙断连",
  "evidence": "蓝牙偶尔断连"
}
```

可借鉴：

- `sentiment_reviews.py`。
- `negative_diagnosis_reviews.py`。

验收标准：

- LLM 输出必须是固定 JSON。
- 后端或脚本必须校验 UX 标签是否属于当前商品 taxonomy。
- 失败数据写入 error 文件。
- 支持断点续跑，避免重复调用 LLM。

当前完成情况：

- NLP `/analyze` 已接受可选 `taxonomy`。
- 后端 `AnalysisJobService` 会把当前商品绑定 taxonomy 传给 NLP。
- NLP prompt 明确要求优先输出 `uxPrimaryLabel` 和 `uxSecondaryLabel`；`aspect` 只作为兼容旧系统的辅助字段。
- 后端会把非法或缺失的 UX 二级标签归入“无明显问题”，避免错标签污染聚合结果。

### 阶段 4：正面卖点与 Aha Moment

目标：系统不只找问题，也能发现产品优势和用户惊喜点。

输出示例：

```json
{
  "sellingPoint": "佩戴舒适",
  "positivePhrase": "戴久了也不累",
  "ahaMoment": "跑步时很稳，不容易掉",
  "ahaScore": 0.87
}
```

可借鉴：

- `build_positive_insights.py`。
- `build_positive_views.py`。

验收标准：

- 输出正面卖点排行榜。
- 输出高频正面短语。
- 输出代表性 Aha Moment。
- 前端可以展示卖点卡片或卖点词云。

当前完成情况：

- 已新增 `review_semantic_labels`，保存每条评论的方面、情感、UX 一级标签、UX 二级标签、标准原因、证据、置信度和负面强度。
- `AnalysisJobService` 在物化 `review_aspects` 时同步写入语义标签。
- 已新增 `GET /api/v1/positive-insights?productCode=...&limit=5`。
- 当前卖点算法采用和缺陷分析类似的可解释思路：从正面评论中的预置 UX 高频标签聚合，而不是另起复杂聚类模型。
- 聚合口径是 `sentiment=POSITIVE` 且 `uxSecondaryLabel` 有效，按 `aspect + uxPrimaryLabel + uxSecondaryLabel` 汇总。
- 排序公式为 `score = mentionShare * 0.45 + positiveRate * 0.35 + avgConfidence * 0.20`。
- 前端已新增“卖点”模块，并在总览展示 Top 1 卖点。
- 代表性 Aha Moment 和正面短语仍属于后续增强，不属于当前保守版本。

### 阶段 7：产品迭代优先级

目标：从“问题优先级”升级到“产品迭代建议”。

建议指标：

```text
negativeImpactScore = problemFrequency * avgNegativeIntensity
positiveSignalScore = positiveMentions + primaryMentions * 2 + ahaMomentCount * 5
iterationPriorityScore = negativeImpactScore * (1 + min(positiveSignalScore / 1000, 0.30))
```

优先级：

```text
I0：必须优先修复
I1：近期优化
I2：持续观察
I3：低优先级
```

可借鉴：

- `build_iteration_priority.py`。

验收标准：

- 输出产品迭代优先级表。
- 能解释为什么某个问题排在前面。
- 能结合负面痛点和正面卖点。

## 5. 最终答辩口径

项目最终应这样介绍：

> 本系统是一个基于 LLM 的电商产品评论 VOC 分析与产品改进决策系统。系统首先通过 Python 采集电商商品评论，将原始评论保存为 JSONL 文件；随后通过规则和 LLM 对评论进行数据清洗、情感识别、负面强度评分、UX 问题标签映射和正面卖点提炼；后端将结构化结果入库，并计算问题优先级、趋势变化、标准原因分布和产品迭代优先级；前端通过表格、趋势图、词云、矩阵图、卖点卡片和迭代优先级看板展示结果，最终形成从评论采集到产品改进决策的闭环。

## 6. 优先级建议

如果时间非常紧，按以下顺序做：

1. 先把后端 Maven 环境补好并跑通后端测试。
2. 把 crawler 采集完成后的 JSONL 自动导入同一 `productCode`。
3. 增加质量抽样评估，证明 UX 标签和情感判断质量。
4. 新增产品迭代优先级接口和前端展示。
5. 扩展正面 Aha Moment 和正面短语提炼。
6. 最后补正式鉴权、异步任务和报告导出。

最小可交付版本：

```text
raw_reviews.jsonl
  -> 保真清洗
  -> cleaned_reviews.jsonl
  -> 后端导入
  -> 商品绑定 UX taxonomy
  -> analysis/start
  -> 问题/趋势/词云/验证/卖点展示（按 UX 二级标签）
```

完整增强版本：

```text
爬虫采集
  -> 清洗
  -> LLM 情感
  -> LLM 负面诊断
  -> 正面卖点
  -> 标准原因
  -> 迭代优先级
  -> 多品类前端看板
  -> 质量评估
```
